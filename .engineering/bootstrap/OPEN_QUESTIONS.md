# Open Questions（待澄清问题）

> Owner: `project-bootstrap`。
> `BLOCKING_QUESTION` 的判定标准（二者同时满足）：① 会改变一项重大架构决策；② **不存在**可以安全采用、之后可低成本回退的假设。

## 本轮结论：**没有 BLOCKING_QUESTION**

每一个已识别的未知都存在一个安全假设与有界的回退路径，因此规划继续，Planning Gate 预期为 `PASS_WITH_ASSUMPTIONS` 而不是 `HOLD`。

| ID | 问题 | 影响的决策 | 采用的安全假设 | 回退代价 | 优先级 |
|---|---|---|---|---|---|
| Q-01 | 主数据库用 PostgreSQL 16 还是 MySQL 8.4？ | 存储选型、索引能力 | PostgreSQL 16（理由见 `TECH_SELECTION.md`） | **Phase 0 内极低**（尚无数据）；Phase 3 之后升高 | 高 — 建议在 Phase 0 开始前答复 |
| Q-02 | 库存是否需要库位（Location）级精度？ | 库存台账主键维度 | A-11：维度预留 + 哨兵 `NO_LOCATION` | 低（启用不改主键） | 中 |
| Q-03 | 是否与 `wms-platform` 对接，由 WMS 承担物理执行？ | 系统边界、集成架构 | MVP 自建库存账 + `InventoryExecutionPort` 预留 | 中（需要设计过账回执协议） | 中 |
| Q-04 | 多租户隔离要求（共享库 / 分库 / 数据驻留）？ | 数据架构、合规 | A-10：共享库 + `tenant_id` 强制过滤 | 中（`tenant_id` 已在，可按租户迁库） | 中 |
| Q-05 | 库存计价方法（移动加权平均 / FIFO / 个别计价）？ | 库存价值与 COGS 模型 | A-09：移动加权平均 | **有界**——流水不可变，任何方法都可重算 | 中 |
| Q-06 | 是否需要多币种与汇率折算？ | 金额值对象、财务模型 | A-08：单本位币，币种字段预留 | 低（加法变更） | 低 |
| Q-07 | 团队规模与期望交付周期？ | Roadmap 周期、是否并行 | A-07：1–5 人 | 无架构影响，只影响排期 | 低 |
| Q-08 | 是否有真实的税务/发票/电子档案合规要求？ | 是否进入 FUTURE_SCOPE | 当前 `OUT_OF_SCOPE` | 中 | 低 |
| Q-09 | 超收是否允许？允许比例？负库存是否允许？ | 采购与库存的业务规则 | 默认禁止超收、禁止负库存，经 CAP-P11 配置放开 | 低（配置项） | 中 — Phase 4 前需答复 |
| Q-10 | RPO/RTO 的真实要求？ | 备份与恢复方案 | NFR-07：RPO 15min / RTO 4h（`ASSUMED`） | 低 | 低 |
