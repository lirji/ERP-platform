已绑定用户登录后，管理员配置角色和数据范围；基础资料维护员建立单位、商品、SKU、供应商、仓库；采购员建单提交；审批员在待办池处理；仓管员分批收货；采购/财务人员查看库存、收货及应付生成结果。所有页面调用真实 API，演示数据通过现有数据库种子工具写入。

| 角色 | 首批主作业 | 边界 |
|---|---|---|
| 租户安全管理员 | 普通角色、权限、数据范围、已有用户角色分配 | 仅本租户；受保护管理员授权不通过普通角色编辑器维护 |
| 主数据维护员 | 单位、商品、SKU、供应商、仓库维护 | 引用后关键字段受限，不物理删除 |
| 采购员 | 建单、修改草稿、提交、取消、关闭剩余、查询 | 仅获授权单据与仓库；不能提供任意操作者或快照 |
| 审批员 | 可处理采购待办、批准、驳回 | 用户确认：角色待办池，有权限且非提交人；无会签/指定审批人 |
| 仓管员 | 获授权订单分批收货、库存及流水查询 | 已批准、未收齐、仓库在授权范围内 |
| 财务查询员 | 查看应付及来源收货单 | 仅应付查询，不新增付款/核销操作入口 |

允许一人多角色，但不能审批自己提交的采购单。系统管理员不因管理权限自动获得采购审批或财务查看权限。

## 范围边界

首批含采购必需主数据：单位、商品/SPU、SKU、供应商、仓库；商品类目和供应商结算方式若选填可空，已有有效值可查询，不强制扩展完整维护中心。客户维护随销售闭环交付，移出首批；库位作业、批次自动分配、采购申请、报价、退货、文件导入导出、附件也不纳入本批。收货沿用现有无库位桶及手工批次规则。

组织树与用户目录首批只读，用于已存在公司的资料选择和已绑定用户授权；组织创建/搬迁、开户、身份重新绑定不是首批切片。首个安全管理员通过受控初始化绑定既有 auth 身份，不能开放匿名初始化入口。普通员工不得借角色管理为自己提升安全管理员权限。

复用 OIDC/PKCE、Java21/Spring Boot、PostgreSQL、Flyway、MyBatis、状态机、编号、Outbox、财务投影、已有测试与 Compose。不再生成本地 OIDC 客户端。生产客户端/回调由 auth 项目生成，生产部署不属于本次规划授权。

## 验收场景

1. A、B 两租户分别配置两个公司、不同仓库和角色；接口查询/导出外的所有首批读写按授权集合过滤，伪造 tenantId/operatorId 被拒。
2. 管理员给普通用户分配角色，下一次请求生效；撤销后不可继续审批/收货；普通角色不可获得受保护管理权限。
3. 建立商品/单位/SKU、供应商、仓库，采购引用后改名不改历史快照，关键字段修改被拒。
4. 建采购单→提交→提交人从待办池被排除→另一审批员驳回→修改→重提→批准。
5. 分三次收货，单据累计、库存流水/余额及最终应付金额一致；超收、未批准收货、跨订单行、重复命令均安全拒绝或返回原结果。
6. 收货提交成功但应付未生成时显示处理中；投递失败时显示可诊断状态而不是假装零应付。重试不多生成一张应付。
7. 同一公司无仓库权限不可读该仓库存或通过单据/应付来源绕过边界；403/404/409/5xx 区分展示。
