# P9 快照报表契约

五类快照：INVENTORY、PURCHASE、SALES、AR、AP。查询仅在已发布快照内进行，响应携带 snapshotId/创建时间；不把历史快照标为实时数值。
库存以六维桶为一行，数量/预占/锁定/在途及已知成本直接来自库存权威导出。
采购/销售以原收发货行为一行，展示原数量/金额及累计退货；净额为原金额减独立退货金额。按原单业务日期归组，非“当日现金收入”。历史无金额快照保持未知，不统计为真实零价。
AR/AP 账龄以财务单创建日期为基准，是未核销账龄，不是合同逾期天数；净未核销=max(0,原额-红字-已核销)。单独展示实收付和已核销。

重建通过所属模块的类型化端口读权威事实，键集分页最多1000行；reporting 无跨模块 SQL。
任务持久化 kind/cursor/startFingerprint/state，分批数据与检查点同事务。单任务行锁串行执行步骤；进程重启从已提交游标恢复。
完成全量扫描后再核对来源指纹，发生变化则标记 STALE 并保留上次快照，禁止发布混合时点数据。稳定来源的开始/结束期间存在共同一致时点。发布与任务完成同事务。
先支持本地/内网管理 CLI 重建；不新增无鉴权公网刷新接口。

运行：构建后执行 `scripts/rebuild-report.sh TENANT KIND [JOB_ID]`；ERP_DB_* 显式环境覆盖 .env。JOB_ID 省略则启动或接续同类型 BUILDING 任务；来源变动返回失败而不是发布混合数据。日志包含恢复任务 ID。可用 cancel 失效候选，再通过 purgeStep 每批至多1000行回收指定非当前终态快照；当前快照不会被清理。该管理操作仅处理可重建报表数据，不清理业务表。
