# P5 销售用例边界与验收说明

2026-09-22 接手 Claude 中断实现。P5 提供模块内 `SalesOrderService`，尚未新增 HTTP Controller；这里记录内部调用约定，不声称 HTTP 权限或生产登录链路已验收。

## 用例与事务

- 创建订单：1–200 行，数量为正、单价非负，最多六位小数；金额 HALF_UP 四位。客户授信上限由可信调用方从主数据读取，不能开放为客户端可任意设置的参数。
- 信用超限：先 `requestCreditApproval`，由审批端口完成审批；创建时传 `creditApprovalId`。服务校验实例归属、状态及订单内容摘要；数据库唯一索引禁止一个实例重复使用（取消也不恢复使用权）。普通下单传 null。该签名替代未交付草稿中的布尔参数，无已发布消费者迁移。
- 订单提交、审批、预占、出库、取消先锁同一订单行；状态写入附版本条件并检查影响行数。事务超时 30 秒。
- 只有 APPROVED 可预占；库存不足整笔回滚，订单仍为 APPROVED。重复预占返回冲突。
- APPROVED / PARTIAL_FINISHED 且已预占可出库；订单行必须属于当前订单。预占消耗、库存扣减、出库单、订单累计量和 Outbox 同一事务。
- 出库后可发运，发运后才能签收；重复操作或跨租户不存在的单据报冲突。订单 FINISHED 表示订购量全部出库；客户签收由发货单独立记录。
- 未出库订单取消释放全部预占及信用；已经出库不能取消。`closeRemaining` 仍不是 P5 已提供的用例，原错误提示中的该建议仅为后续方向。

## 事件与持久化

`ShipmentPosted.v1` 在出库事务写入，沿用 EVENT_CATALOG 的应收触发点；签收不是生成应收的触发点。
当前 payload 的 `parentType/parentId/parentNo/childType/childId/childNo` 支持销售订单与发货单双向追溯。
P6 财务所需的金额、币种、客户等载荷尚待 P6 细化，当前不能声称已完成财务闭环。

V80 为 Claude 留下的五张销售表；新增 V81 补信用审批引用唯一约束、金额非负和签收前置约束。未改写 V80，以兼容可能已执行该迁移的环境。迁移仅在隔离 `erp_it` 中验证，未执行生产部署。

## 验证与边界

`OrderToShipE2EIT` 覆盖 ROADMAP P5 五项出口、单据图双向追溯、真实审批绑定、串单/跨租户拒绝、多行回滚、并发信用占用/分批出库/预占取消。
历史 OIDC 阻塞仍在，不能将模块内部调用测试当成已验证 HTTP 认证授权。审批人为可信内部入参，生产入口必须从已验证身份和权限取得。
本期未新增中间件、远程服务、前端或 HTTP 端点；审计沿用订单状态迁移留痕，通用写操作 AOP 与 HTTP 审计不在本次验收证据中。
业务日期目前沿用既有单一 Asia/Shanghai 部署约定；按租户时区取业务日期的完整链路尚未实现，不能宣称全租户时区支持。
