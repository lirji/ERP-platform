# 普通角色与安全管理员

首批FBL-S1增加分页角色目录、新建/改名/启停与功能权限。入口为`/workbench/#/iam/roles`。旧`/iam/roles`仍返回数值ID数组；新管理接口为字符串ID/版本。

管理写操作需同时具备`iam:role:write`及受保护角色授予的`iam:security:admin`。目录中不含安全管理员权限，受保护角色不能通过普通接口修改或分配。UI隐藏按钮只是提示，服务端仍逐次判权。

首次初始化只允许运维显式指定已有绑定身份：

```sh
psql "$ERP_ADMIN_DATABASE_URL" -v ON_ERROR_STOP=1 \
  -v tenant_code=已绑定租户编码 -v username=已有用户 \
  -f deploy/sql/bootstrap-security-admin.sql
```

连接串由受控凭据机制注入，不粘贴到文档或提交。脚本验证有效OIDC绑定，不创建用户；重复执行不重复授权；同名普通角色或停用受保护角色冲突时拒绝自动提升。必须核对目标环境及账户，Git发布不授予生产初始化权限。

所有新写操作带UUID `Idempotency-Key`。登记、业务变更、前后配置审计和首次响应同事务提交；失败全回滚。客户端在结果未知时保留原键重试，不能自行换键制造新命令。重放仍验证当前身份与授权，冲突409要求重新读取版本。每个编辑动作独立提交，基本信息和功能权限分别保存。

角色配置修改目前使用租户行锁串行化并在锁内重查管理员权限，事务上限10秒。完整业务命令与授权修订的共享/排他锁协议在S2B实施。目录权限批量获取，不逐行发SQL。新增V122命令记录、V123角色版本/保护字段、V124配置审计；不删除去重记录或回写既有迁移。

S2A已提供指定组织子树/公司集合配置与回显。组织查询返回授权森林：安全管理员管理本租户全部启用组织；其他角色按iam:org:read的主体范围读取，SELF/DEPT仅本组织；指定公司包含该公司子树。不可见父节点以森林根表示，最多2000节点和64层，超过或存在环明确422。仓库授权仍由S7B实施，当前只能NONE。

新业务入口按目标动作获取ActionScope，多个适用角色范围OR；每角色仍独立，不把其他权限角色的范围拿来放大授权。组织前缀使用参数绑定的left等值比较，路径中的%/_不是SQL通配符。缺失指定集合无grant；停用角色/组织不授予新访问。旧上下文只保留/me枚举摘要，指定范围不再降级成部门范围，旧查询明确拒绝；新HTTP业务查询逐片绑定新表达式。用户分配与完整在途授权锁由S2B实施。

验证工具：`scripts/role-management-browser-smoke.cjs`使用真实本地Casdoor和ERP，模拟服务器已提交但响应丢失，验证重复点击仅一角色，再配置权限并停用测试角色。测试角色无用户绑定，保留可审查事实；真实数据不写死在UI。

范围浏览器验证：`ERP_SMOKE_SCOPE=1 node scripts/role-management-browser-smoke.cjs`，从真实组织接口选择公司，保存后关闭/重开回显。V125明细表有租户复合外键；范围配置与版本/审计/幂等响应同事务。
